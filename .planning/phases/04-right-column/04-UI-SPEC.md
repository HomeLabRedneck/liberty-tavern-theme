## Spacing Scale

All values are multiples of 4. Existing tokens from `common.scss` are preserved; Phase 4 adds new usages.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Hexagon-to-name gap; name-to-count gap in badge tiles |
| sm | 8px | Badge grid gap (2×2); house-rules eyebrow tick offset |
| md | 16px | Badge tile internal padding; house-rules list top padding; panel-to-panel not used (see lg) |
| lg | 24px | Vertical gap between the Badges panel and the House Rules panel; badge grid outer nothing |
| xl | 32px | Gutter between main content and the rail (D-1) |
| 2xl | 48px | Inherited from banner grid — not used in new surfaces |
| 3xl | 64px | Inherited horizontal page padding — rail aligns inside this, not a new value |

Exceptions (decorative measurements, not spacing tokens):
- **Rail width ≈ 280px** (D-1; matches the existing banner aside column `grid-template-columns: 1fr 280px` in `common.scss §8` line 732 — reuse the same 280px so the rail visually lines up under the banner stats box).
- **House Rules box padding: 14px** (D-4). Non-multiple-of-4 is locked by the mockup; keep as-is.
- **Hexagon icon: ~40px wide** with `clip-path` polygon — a glyph container size, not a layout token.
- **Hairlines: 1px** borders/rules (badge tile border, house-rules oxblood border, badges header rule) — sub-token stroke widths.
- **Breakpoint: 1160px** (D-1) — a media-query threshold, not a spacing value.

## Component Specifications

### Surface 0: Right Rail Container + Grid Override (COL-01, COL-02, D-1)

The rail mounts via a Glimmer connector at `after-main-outlet` (`connectors/after-main-outlet/tavern-right-column.hbs` → `<TavernRightColumn />`). A CSS Grid override on the homepage content wrapper places the rail beside the main content, scoped to discovery routes.

**Route scoping**

Render/show the rail only on the homepage discovery list views: **Rooms** (`.category-boxes`), **Trending**, **Latest at the Bar**, **Top Shelf** (all `.topic-list`). Reuse the existing body-class gate pattern from `common.scss §8` line 840 — these views carry `body.navigation-categories` (Rooms) or `body.navigation-topics` (Trending/Latest/Top). The grid override and rail visibility must be constrained to those body classes so topic pages and other routes are untouched.

> ⚠ Open item for the planner (not a user decision, from D-1 / SUMMARY): verify the exact homepage
> content wrapper selector live before finalizing — candidates are `#main-outlet-wrapper`,
> `.list-container`, or the regenerated outlet wrapper on this Discourse version. Also verify that
> `after-main-outlet` mounts the rail on `.topic-list` views (not only `.category-boxes`); a
> discovery-list outlet may be needed. Same live-verification discipline as Phase 3. The contract
> values below (280px rail, 32px gutter, 1160px breakpoint) hold regardless of which wrapper wins.

**Grid override — homepage content wrapper (scoped to discovery routes)**

| Property | Value | Rationale |
|----------|-------|-----------|
| `display` | `grid` | Two-column layout: main + rail |
| `grid-template-columns` | `minmax(0, 1fr) 280px` | Main fluid, rail fixed ≈280px (D-1; matches banner aside width) |
| `column-gap` | `32px` | Gutter between main and rail (xl token, D-1) |
| `align-items` | `start` | Rail top-aligns; does not stretch to main height |

- On the **Rooms** view the rail begins at the Trending strip / Rooms list row — **below** the full-width dark banner and its stats box (the banner + `.tavern-trending` span the full content width; they are not inside the grid's main column narrowing). On the other three views (no banner) the rail starts near the top, aligned with the topic-list heading. Achieve this by ensuring the full-width banner/trending elements are not constrained by the grid main column (they precede the grid or span both tracks) — the planner confirms placement live.

**`.tavern-right-column` (rail container)**

| Property | Value |
|----------|-------|
| Font family | `var(--font-serif)` (body context) |
| Display | `flex; flex-direction: column` |
| Gap | `24px` (lg token — vertical gap between Badges and House Rules panels) |
| Background | transparent (sits on the cream page) |
| Width | fills the 280px grid track |

**Breakpoint behavior — see the Interaction Contract "Responsive hide / reflow" spec below.**

**Visual hierarchy (rail focal point).** The **Badges panel header + hairline is the rail's primary focal point** — the largest type on the rail (24px Playfair italic) and the first element the eye lands on, ahead of the badge grid and the House Rules box beneath it. The House Rules box is the secondary anchor (its oxblood border draws attention as a distinct bounded element). Order top-to-bottom: Badges header → badge grid → House Rules.

## Interaction Contract

### Responsive hide / reflow (COL-01, COL-02, D-1) — primary interaction spec

| State | Threshold | Behavior |
|-------|-----------|----------|
| Rail visible | viewport **≥ 1160px** | Two-column grid: main content + 280px rail with a 32px gutter. Rail sits beside main content — not below, not overlapping. |
| Rail hidden | viewport **< 1160px** | `@media (max-width: 1159.98px)` (or `max-width: 1160px`): the homepage content wrapper reverts to a single column (`grid-template-columns: 1fr` or `display: block`), and `.tavern-right-column` is set to `display: none`. Main content reflows to full width. **No horizontal scroll, no broken layout, no leftover empty grid track.** |

- The breakpoint must reset BOTH the grid template on the content wrapper AND hide the rail element, so no phantom 280px column remains at narrow widths.
- Mobile-specific custom layouts are explicitly out of scope (REQUIREMENTS "Out of Scope") — below 1160px the rail is simply removed and Discourse's native responsive behavior handles the rest.

### Badges panel

- No interactivity beyond native link behavior. Badge tiles may optionally link to `/badges/{id}` via standard `<a href>` (Discourse router) if the executor chooses; no JS action, no hover-card, no animation is specified by the mockup.
- Loading: House Rules (static) renders immediately; the Badges panel appears once `/badges.json` resolves.

### House Rules panel

- Fully static. No interactivity, no hover, no click behavior. Renders the four locked rules immediately on mount.

### Rail as a whole

- Conditionally rendered only on the homepage discovery views (Rooms/Trending/Latest/Top) via the body-class gate — not on topic pages or other routes.
